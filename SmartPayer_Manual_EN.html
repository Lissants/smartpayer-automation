Getting started
First-time installation and launching the GUI

Launching SmartPayer (every time)

Once set up, you open SmartPayer the same way every time — no need to open Python or any code manually.

  1. Open the SmartPayer Automation folder.
  2. Double-click run_gui.bat.
  3. The SmartPayer graphical interface will open and is ready to use.
Bookmark this stepYou will run run_gui.bat every single time you want to use SmartPayer. Think of it as your app launcher.

First-time setup — install prerequisites

Only done onceAfter this is complete, you never need to repeat it. Just launch run_gui.bat going forward.
  1. In the SmartPayer folder, locate install_prerequisites.bat.
  2. Double-click it. A terminal window will open and begin the process.
  3. The installer automatically downloads and configures Python and all required libraries.
  4. Wait for the terminal to finish — a confirmation message will appear when done.
  5. Close the terminal. You are now ready to launch with run_gui.bat.
Terminal closes instantly?Right-click install_prerequisites.bat and choose "Run as administrator". Some systems require elevated permissions to install software.

Input files
Two ways to provide your raw SAP data file

SmartPayer accepts a raw SAP export file as its input. There are two equivalent ways to load it — use whichever is more convenient.

Method A — File picker

  1. Click the Browse button on the main interface.
  2. A standard file dialog will open. Navigate to your SAP export file.
  3. Select the file and click Open. The path will appear on screen.

Method B — INPUT folder

  1. Open the SmartPayer Automation folder.
  2. Open the INPUT subfolder inside it.
  3. Copy or move your raw SAP file into this folder.
  4. The application will detect the file automatically when you run the automation.
Which method should I use?Both produce identical results. Use Browse if your file is stored elsewhere. Use the INPUT folder if you prefer a consistent drop-zone workflow.
One file at a timeSmartPayer processes one input file per run. If multiple files are in the INPUT folder, only the most recent one is used. Remove older files to avoid confusion.
Daily rate
Configuring the interest rate applied to invoices
Default rate
0.022%
per day — applied automatically unless changed

Keeping the default rate

When automation starts, a prompt confirms the current rate. Click Yes – Keep Rate to proceed with 0.022%/day.

Changing the rate

  1. When prompted, click No – Change Rate.
  2. A text field will appear. Type your new daily rate as a decimal percentage.
  3. Confirm the entry. The new rate will be applied to this run.
FormatEnter as a percentage decimal — e.g. 0.025 for 0.025%/day. Do not include a % symbol.
ScopeThe changed rate applies to the current run only. The default of 0.022%/day is restored on the next launch.
Calendar picker
Selecting processing dates for your invoice run

The calendar picker lets you specify which dates the automation uses when generating invoice letters.

Minimum dates required
3
Maximum allowed
4
Selecting more than 4 is not permitted

How to select dates

  1. Click the calendar to open the date picker.
  2. Click your first date — it will be highlighted.
  3. Continue clicking additional dates individually.
  4. Ensure you have selected a minimum of 3 dates before proceeding.
  5. A 4th date is optional. A warning appears if you attempt to select more than 4.
Required minimumThe automation will not proceed with fewer than 3 dates selected. A validation message will notify you.

Email recipients
Managing who receives each invoice letter

The recipients list maps each client name to one or more email addresses. SmartPayer uses this list to route generated PDFs to the correct inboxes.

Viewing the list

Click Recipient List to open the full table — client name, primary To address, and CC address.

Importing recipients

Prepare your recipients in an .xlsx spreadsheet, then either:

  1. Click Import Recipients on the main interface, or
  2. Open Recipient List → click Import XLSX inside the dialog.

Managing recipients

ButtonWhat it does
Delete allPurges the entire recipient list. Cannot be undone — re-import from your XLSX afterwards.
SaveSaves all additions and edits made during the current session.

Special case — clients with multiple bill-to parties

For clients like CV. INDRA JAYA and SEJATI MANDIRI that have more than one bill-to party number, create a separate recipient row for each — with the bill-to number appended to the client name.

CV. INDRA JAYA 3001421 → recipient-a@email.com
CV. INDRA JAYA 3100432 → recipient-b@email.com
SEJATI MANDIRI 4002100 → recipient-c@email.com
Why split entries?Each invoice letter is generated per payer name. Without split entries, all letters for a multi-party client would go to the same address — missing the correct contacts.

Starting the run

  1. Open SmartPayer by double-clicking run_gui.bat.
  2. Verify your input file is loaded (via Browse or INPUT folder).
  3. Confirm rate, calendar dates, template defaults, and recipient list are correct.
  4. Tick or untick Auto-send email as needed.
  5. Click Run Automation.
  6. Monitor the progress log. Do not close the application while running.
When it finishesA completion message appears. PDFs are in Generated_Letters. If auto-send was on, check the log for any delivery failures.
Managing output
Organising generated PDF letters

After a run, all generated PDFs land in Generated_Letters. SmartPayer includes tools to keep this folder tidy.

Organise PDF output

Click Organise PDF Output to sort all files in Generated_Letters into sub-folders by name prefix.

How it works
Generated_Letters/
├── SmartPayer April 2026/
│   ├── SmartPayer April 2026 - CV. ABADI.pdf
│   └── SmartPayer April 2026 - PT. MAJU.pdf
└── SmartPayer May 2026/
     └── SmartPayer May 2026 - CV. ABADI.pdf

Folders are created automatically if they do not exist. Files sharing the same prefix are grouped together.

When to use thisRun Organise PDF Output after every automation run, or before archiving a month's letters.

Compress completed PDFs Deprecated

Previously used to compress PDFs in Generated_Letters. Its function has been superseded by Organise PDF Output. This button can safely be ignored.

Deprecated featureUse Organise PDF Output instead — it is the recommended way to manage generated files going forward.
Retry & troubleshoot
Resolving failed email deliveries

When SmartPayer cannot find a matching recipient for a generated letter, that delivery is marked failed. You do not need to re-run the entire automation — use the retry workflow instead.

Why deliveries fail

A delivery fails when the payer name on a letter does not match any entry in the recipients list. This typically happens when a new client appears in the SAP export for the first time, or when a client name has changed.

Retry workflow

  1. After the run, check the log for entries marked Failed. Note the client names.
  2. Click Recipient List to open the recipients table.
  3. Add the missing clients with their correct To and CC email addresses.
  4. Click Save.
  5. Click Retry Failed Emails.
  6. SmartPayer resends only the previously failed letters — no new PDFs are generated.
Retry is targetedOnly failed letters are resent. Successfully delivered letters are not duplicated, and the SAP file is not reprocessed.
